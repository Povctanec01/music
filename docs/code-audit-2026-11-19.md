# Проверка проекта Music — 19 ноября 2026

Это отчёт о первоначальном аудите. Последующие изменения версии 1.1.0 и новые
результаты проверок описаны в [reliability-1.1.0.md](reliability-1.1.0.md).

Проверены Android-код, веб-клиент, Python-сервер, конфигурация сборки и контракт обновлений.
Найдены и исправлены ошибки. Успешная сборка и тесты не означают, что каждый
аппаратный сценарий Android уже проверен на телефоне: границы проверки перечислены ниже.

## Исправления

### Сервер

- `Range: bytes=-N` теперь возвращает последние N байтов. Обратные, пустые и
  недопустимые диапазоны возвращают 416 вместо отрицательного Content-Length и зависания.
- HEAD не записывает JSON/данные в тело и не портит следующее обращение по keep-alive.
- APK-прокси закрывает соединение, если upstream не прислал Content-Length.
- Убрано двойное URL-декодирование путей загрузки и внутренних путей обложек.
  Имена с буквальным `%20` сохраняются и открываются корректно.
- Ошибка Mutagen на повреждённом аудио больше не обрывает HTTP-ответ при загрузке.
- Обновление обложек сохраняет исходный sidecar, если он является единственным источником картинки.
- Ошибка одной обложки не останавливает весь фоновый проход.
- API библиотеки передаёт длительность и доступные теги. Раньше длительность всех
  веб-треков была нулевой и сортировка по длительности не работала.
- Multipart обрабатывается без `cgi`: небольшие буферы и временные файлы на диске,
  поддержка нескольких файлов, UTF-8 и границ между сетевыми порциями.
- Ужесточена проверка тегов версии; некорректный JSON prefetch получает 400;
  неизвестный API-маршрут получает 404 вместо HTML главной страницы.
- Управляющие символы исключены из ASCII-части Content-Disposition.

### Веб

- Web Audio создаётся при первом воспроизведении: повторная инициализация эффектов
  React StrictMode больше не пытается создать второй источник для одного audio-элемента.
- Исправлены измерение громкости после собственного усиления и возобновление
  AudioContext при выключенном выравнивании. При выключении компрессор работает с ratio=1.
- Завершение очереди останавливает audio; выбранный повторно трек и одиночное
  перемешивание могут стартовать заново. Исправлен возврат по истории shuffle.
- Удаление убирает трек из очереди. Ошибки play/upload выводятся в интерфейс;
  остаток времени прослушивания сохраняется при паузе и смене трека.
- Библиотека использует длительность и теги сервера; устранён дубликат компонента обложек.
- Повреждённые значения и недоступность localStorage больше не ломают старт интерфейса.
- Исправлено округление времени на границе минуты, проверка диапазона экспорта и
  пропуск хвоста аудио при построении волны.
- Убраны предупреждения веб-линтера о зависимостях эффектов и синхронном сбросе состояния.

### Android

- Неправильный URL при проверке сервера возвращает offline вместо исключения вне try.
- Исправлены счётчик загрузки при ответе 200 на Range, проверка Content-Range,
  ошибочное завершение при 416, проверка итогового размера и отмена активного HTTP-запроса.
- «Играть следующим» в shuffle добавляет трек следующим, вместо немедленной смены.
  Удаление убирает трек также из предыдущих элементов очереди и shuffle-pool.
- Восстановление очереди ищет сохранённый mediaId, если часть файлов была удалена.
  Переключение shuffle сохраняет состояние воспроизведения; отмена затухания восстанавливает громкость.
- Изменения статистики DataStore больше не вызывают повторное сканирование папки.
  Сканирования сериализованы, отмена корутины не публикует устаревший результат.
- Sidecar не удаляется, если удаление аудио не удалось. Ошибка выдачи прав на папку обрабатывается.
- Ручки Android-редактора используют координаты всей волны и не перезапускают
  обработчик жеста на каждом движении.
- Обрезка выполняется по PCM-кадрам, а не приблизительно целыми буферами декодера;
  запрашивается 16-битный PCM, ресурсы освобождаются при ошибках/отмене.
- При построении волны учтены число каналов и little-endian PCM; декодер освобождается в finally.
- Результат старой задачи построения волны не заменяет новый выбор. Ключ кэша редактора
  включает сервер, путь, размер и mtime; незавершённый файл не используется как готовый.
- Исправлено состояние отменённой установки APK; наличие обновления учитывает APK asset.
- Обложки декодируются с ограничением размера, LRU учитывает байты. Сканирование
  не декодирует всю библиотеку заранее; неиспользуемые StateFlow освобождают картинки,
  а видимый компонент запрашивает вытесненную картинку повторно.
- В сборке явно выбраны установленные Build Tools 36.1.0. Исправлен локальный,
  игнорируемый Git путь SDK; использованы существующий JDK 21 и кэш Gradle проекта.

## Автоматические проверки

| Проверка | Результат |
|---|---|
| `npm --prefix web run build` | TypeScript и production/PWA сборка успешны |
| `npm --prefix web run lint` | Без ошибок и предупреждений |
| `npm --prefix web test` | 9 тестов успешны |
| `python -m unittest discover -s server -v` | 11 тестов успешны |
| `:app:testDebugUnitTest` | 9 тестов успешны: 8 новых и 1 исходный шаблонный |
| `:app:lintDebug` | 0 ошибок; 34 предупреждения |
| `:app:assembleDebug` | Debug APK собирается |
| `git diff --check` | Без ошибок пробелов |

Серверные тесты используют временную библиотеку и настоящий локальный HTTP-сервер.
Внешние ответы APK подменены; покрыты неизвестная длина APK, keep-alive после HEAD,
диапазоны, обход путей, multipart с бинарными данными и порциями по 7 байт,
загрузка/удаление, сохранность обложек, длительность WAV и теги версий.

Веб-тесты проверяют сортировку/группы/избранное, рекомендации, shuffle, хранилище,
волну, PCM WAV и схему выравнивания громкости. Android unit-тесты проверяют
PCM-границы, форматы, пути обложек, поиск server art и неправильные URL.

Предупреждения Android Lint: уведомления о версиях зависимостей, неиспользуемые
ресурсы, избыточные проверки SDK/label, рекомендации KTX, cleartext HTTP и
экспортированный media service. Они не скрыты baseline или отключением Lint.
Обновление всех библиотек в рамках этого аудита не выполнялось.

## Сквозные проверки в браузере

Использована отдельная локальная библиотека с синтетическим стерео WAV, без изменения
настоящей музыки. Пройдены:

- загрузка библиотеки, поиск и очистка поиска;
- сортировка по названию и по реальной длительности, раскрытие альбома;
- добавление в избранное и фильтр избранного;
- запуск, повторный запуск, пауза, перемотка и громкость;
- следующий/предыдущий трек, shuffle и возврат по истории;
- автоматический переход после окончания;
- проверка сервера, отображение тестового релиза APK и сохранение настройки выравнивания;
- выбор трека в редакторе, декодирование волны, ввод границ, экспорт и загрузка WAV;
- повторная проверка экспорта в финальной веб-сборке с новым multipart-обработчиком.

Экспорт `First.trim.2-4.wav` дополнительно открыт стандартным модулем wave:
длительность **2.0 секунды**, **2 канала**, **16 бит**. Во время проверенных сценариев
ошибок консоли браузера не обнаружено. Наличие реального звука на физических
колонках по этому прогону не устанавливалось.

## Границы проверки и оставшиеся ограничения

1. **Телефон и системные сценарии Android.** Инструментальные тесты на устройстве
   не запускались. ADB в текущем окружении завершался ошибкой создания `\.android`.
   SAF разных провайдеров, фоновые загрузки и уведомления, Bluetooth/гарнитура,
   блокировка экрана, таймер сна, кодеки разных устройств и системный установщик
   требуют отдельного прогона на Android. В том числе нужен замер памяти на большой библиотеке.
2. **Сеть.** Настроенный Orange Pi по LAN отвечает на `/api/health` с 200/`ok`.
   Проверка настроенного Tailscale-адреса завершилась тайм-аутом 3 секунды.
   Это не доказывает ошибку приложения; доступность Tailscale в этом окружении не подтверждена.
3. **Обновление APK.** Контракт и прокси проверены локально с тестовым ответом;
   реальная установка поверх существующего приложения и перезапуск не выполнялись.
   Release-конфигурация по-прежнему использует debug.keystore. Для распространения
   нужен постоянный ключ; смена подписи влияет на возможность обновления установленной версии.
4. **Доступ к серверу.** Upload/delete не имеют авторизации, CORS разрешает любой origin,
   systemd unit запускается от root. Сервер рассчитан на доверенную сеть; открытая публикация
   без ограничения доступа не проверена и небезопасна. Схема доступа автоматически не менялась.
5. **Синхронизация.** Список новых файлов сравнивает относительный путь и размер.
   Изменённое содержимое при том же размере не определяется; контрольных сумм нет.
6. **Форматы и метаданные.** Для сжатых форматов серверу нужен необязательный Mutagen,
   иначе длительность может отсутствовать. Декодирование всех реальных MP3/FLAC/OGG/OPUS/M4A/AAC
   и нестандартных WAV на устройствах не подтверждено синтетическим WAV-тестом.
7. **Незавершённые функции.** Кнопки дополнительных инструментов веб-редактора с
   пометкой «Скоро» отключены в исходном интерфейсе и не реализованы.
8. **Python.** Проверки выполнены на установленном Python 3.12. Зависимость от `cgi`
   удалена, но отдельные интерпретаторы Python 3.13/3.14 не запускались.

## Повторение проверок

Веб-тесты используют встроенную поддержку TypeScript установленного Node 24:

```powershell
npm --prefix web test
npm --prefix web run lint
npm --prefix web run build
python -m unittest discover -s server -v
```

Android: JDK 21, установленный SDK 36.1 / Build Tools 36.1.0 и разрешённая первая
загрузка зависимостей из Google Maven/Maven Central. После наполнения кэша:

```powershell
$env:GRADLE_USER_HOME = Join-Path $PWD '.gradle-home'
$env:ANDROID_USER_HOME = Join-Path $PWD '.gradle-home/android'
$env:JAVA_HOME = 'C:\Users\katal\.gradle\jdks\eclipse_adoptium-21-amd64-windows.2'
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --offline --no-daemon --max-workers=1
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Lint: `app/build/reports/lint-results-debug.html`.
