# Music 1.1.0 — надёжность, безопасность и проверки

Версия приложения: **1.1.0 (43)**. Изменения относятся к исходному коду и собранным
APK этого проекта. Сервис на настоящем Orange Pi автоматически не переустанавливался.

## Что изменено

### Синхронизация по содержимому

Сервер возвращает SHA-256 и версию каждого аудиофайла. Android сравнивает контрольные
суммы, поэтому обновление определяется и при неизменном размере. Сервер проверяет
`If-Match` перед выдачей возобновляемого скачивания: изменившийся файл даёт 412.
Готовый файл проверяется по размеру и SHA-256 до записи в музыкальную папку.
При работе со старым сервером без SHA-256 сохраняется совместимость по размеру;
полная проверка содержимого требует новой версии сервера.

### Очередь после закрытия и перезагрузки

Очередь хранится транзакционно в приватной SQLite-базе. Частичные файлы находятся
в `files/downloads`, а не в очищаемом системном кэше. Ключ временного файла включает
папку, путь и версию источника. При запуске незавершённые операции восстанавливаются
на паузе; пользователь нажимает «Продолжить». Это сохраняет контроль над сетью и
не запускает скачивание самопроизвольно после загрузки Android.

Очередь привязана к исходной папке. Выбор другой папки не перенаправляет уже
запланированные файлы. Дополнение очереди не теряет незавершённые задачи; ошибки
можно повторить. Названия, отличающиеся только регистром, выявляются до загрузки.

### Защита исходных файлов

На сервере загрузка сначала полностью принимается во временный файл. Проверяются
размер и, при наличии заголовка клиента, SHA-256; замена выполняется через `os.replace`.
Обрыв, ошибка записи и неверная сумма не обнуляют существующий файл.

На Android сначала проверяется приватная копия, затем временный документ в SAF.
Исходный документ переименовывается в резервный, и только после этого временный
получает окончательное имя. При ошибке переименования исходный возвращается назад.
Провайдер без нужных операций получает понятную ошибку; небезопасная перезапись
поверх исходного не используется. Пауза/отмена проверяется и во время подготовки замены.

Удаление на Android переименовывает трек в скрытый файл и сохраняет запись корзины.
Доступны «Отменить» и восстановление последнего удалённого трека в настройках.
На сервере трек и sidecar-картинки перемещаются в `.trash`; восстановление доступно
через веб-настройки и кнопку отмены. Занятое имя не перезаписывается.
Корзины не очищаются автоматически и продолжают занимать место.

### Большая библиотека

Локальные метаданные перенесены из общего JSON DataStore в SQLite. Существующий
кэш мигрирует при первом обращении; избранное и статистика не сбрасываются.
Повторный проход переиспользует метаданные и хеши неизменённых файлов, а база
перезаписывает только изменённые записи. Переключение папок убирает старый список
и защищает удаление от устаревшего выбора.

Серверный SQLite-индекс хранит метаданные/хеши между запусками. Первая индексация
читает аудио целиком для SHA-256; следующие проходы используют размер, время
изменения и POSIX ctime. Проверка `/api/health` доступна во время начальной индексации.

### Доступ к серверу

Изменения библиотеки, корзина и принудительная работа с обложками требуют Bearer-ключ.
Без настроенного ключа запись закрыта. CORS ограничен текущим origin и явным списком.
Веб хранит ключ только в sessionStorage и отдельно для каждого сервера. Приватные
данные Android с ключом и очередью исключены из резервного копирования.

Сервис запускается от `music`, с `NoNewPrivileges`, `ProtectSystem=strict`,
`ProtectHome` и ограниченными каталогами записи. Установка и безопасное создание
ключа подготовлены в `server/install.sh`. Подробности — в `server/README.md`.
Обычный HTTP не шифрует трафик; публичное чтение музыки по-прежнему разрешено.

## Как применить

1. Установить release APK 1.1.0 поверх приложения с прежней подписью.
2. Перенести исходники/веб-сборку на Orange Pi и выполнить `sudo sh server/install.sh`
   из копии проекта. Скрипт меняет группу и групповые права только внутри `/srv/music`,
   создаёт `/etc/music-api/token` и перезапускает сервис от пользователя `music`.
3. Ввести содержимое `/etc/music-api/token` в настройках Android и веб-клиента.
4. Если веб размещён отдельно, настроить точные `MUSIC_ALLOWED_ORIGINS`.

Ключ не встроен в APK и не публикуется в репозитории. Старые клиенты без ключа
смогут читать библиотеку, но не смогут загружать, удалять и принудительно обновлять обложки.

## Проверки

Автоматические локальные проверки:

- Python: авторизация, CORS, одинаковый размер при новом содержимом, повторное
  использование SQLite-индекса, If-Match, безопасная замена, отказ диска,
  корзина/восстановление/конфликт имён и прежние HTTP-проверки.
- Веб: ключи разных origins не смешиваются, ошибки доступа понятны, размер и SHA-256
  загрузки передаются серверу. Потоковый SHA-256 сверяется с независимым Node crypto
  на границах блоков и порций; работает и по локальному HTTP. Также проходят прежние
  проверки плеера и редактора.
- Android unit-тесты: сравнение хешей, разделение временных файлов по папкам/версиям,
  обнаружение неполной/повреждённой копии и прежние проверки.

Сквозная проверка браузера выполнена на отдельной библиотеке синтетических WAV:
запрет без ключа, доступ с ключом, корзина и отмена удаления.

Инструментальные проверки находятся в `app/src/androidTest`. SAF-провайдер тестовых
файлов размещён только в debug-сборке; в release-манифесте его нет.
Набор включает проверку реального кодека, безопасной замены/отката/корзины, SQLite,
2000 записей библиотеки, фонового воспроизведения/уведомления/сна,
возобновления HTTP Range и состояния после перезагрузки.

### Повторение Android-проверок

После сборки debug и androidTest APK, на отдельном эмуляторе `MusicTest`:

```powershell
.\tools\test-android.ps1 -SdkPath 'D:\Program Files\appdata\Android\Sdk' -Serial emulator-5580 -Reboot
```

Скрипт отказывается работать с физическим телефоном и эмулятором с другим именем.
Он сохраняет журналы в `tmp/android-checks`, проверяет текст результата JUnit
(одного кода завершения ADB недостаточно), при необходимости выполняет реальную
перезагрузку тестового эмулятора.

Для release используется существующий ключ проекта. Подпись проверяется по
сертификату предыдущего release APK; новый ключ в рамках этой работы не создавался.

### Границы проверки

Физическая Bluetooth-гарнитура в этой среде недоступна. Android запрещает отправлять
защищённый `AUDIO_BECOMING_NOISY` из приложения и shell, поэтому искусственная
рассылка не считается успешной проверкой отключения наушников. Маршрутизацию звука,
разрыв Bluetooth и энергосбережение конкретного телефона нужно проверить на устройстве.
Фоновое воспроизведение и таймер сна проверяются отдельно на эмуляторе.

Обновление APK проверялось через установку пакета поверх предыдущей версии,
с сохранением очереди и частичного файла; диалоги системного установщика отдельно
не автоматизировались. Развёртывание systemd и права на диске настоящего Orange Pi
требуют запуска подготовленного установщика на самом сервере.
