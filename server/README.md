# Music API на Orange Pi Zero 3

Лёгкий HTTP-сервер на Python 3 (только стандартная библиотека).

Поддерживается Python 3.10+. Загрузка файлов использует потоковый обработчик
multipart без устаревшего модуля `cgi`; временные части хранятся на диске.
Для тегов, длительности сжатых аудиофайлов и встроенных обложек можно установить
`mutagen`: `python -m pip install mutagen`. Длительность PCM WAV читается и без него.

## Что слушает

- `GET /api/health` — проверка доступности
- `GET /api/library` — JSON список треков
- `POST /api/upload?path=...` — загрузка multipart, поле `files`
- `DELETE /api/file/{relative_path}` — перенос в корзину, возвращает `trashId`
- `GET /api/trash` — список корзины
- `POST /api/trash/{trashId}/restore` — восстановление без перезаписи существующего файла
- `GET /api/art/{relative_path}` — обложка
- `GET /api/releases/latest?repo=owner/repo` — метаданные APK
- `GET /api/apk/latest?repo=owner/repo` — прокси скачивания APK
- `GET /files/{relative_path}` — скачивание файла, поддерживает `Range`

Папка с музыкой по умолчанию: `/srv/music`.

Изменение библиотеки требует `Authorization: Bearer <token>`. Если ключ не настроен,
запись закрыта (503); неверный ключ даёт 401. Чтение музыки остаётся доступным в вашей
сети. Корзина и принудительное обновление обложек также требуют ключа.
Веб-клиент хранит ключ в sessionStorage отдельно для каждого origin; Android —
в закрытых данных приложения, исключённых из резервного копирования.

Каталог передаёт `sha256` и `version`. SQLite-индекс в `ART_CACHE_DIR/library.sqlite3`
переживает перезапуск и перечитывает метаданные/контрольные суммы изменившихся файлов.
При скачивании можно передать `If-Match: "<sha256>"`: если файл изменился, сервер отвечает 412.
Для загрузки доступны `X-File-Size` и `X-Content-SHA256`. Файл проверяется во временной
копии и только после этого заменяет исходный через `os.replace`.

Корзина расположена в `/srv/music/.trash`, исключена из библиотеки и не очищается
автоматически. При восстановлении занятого имени возвращается 409.

## Проверки

Из корня проекта: `python -m unittest discover -s server -v`.
Тесты создают отдельные временные папки и локальный HTTP-сервер; настоящая
библиотека не изменяется, внешние загрузки подменены тестовыми ответами.

## Установка

```bash
# Из каталога server на Orange Pi; перед копированием web/dist соберите веб-клиент.
sudo sh install.sh
```

Скрипт создаёт пользователя `music`, ключ `/etc/music-api/token` и устанавливает
service с `User=music`, `NoNewPrivileges`, `ProtectSystem=strict` и разрешением записи
только в библиотеку и кэш. Существующие файлы остаются на месте; группе `music`
выдаются права чтения/записи внутри `/srv/music`. Ключ при повторной установке сохраняется.

Введите содержимое `sudo cat /etc/music-api/token` в поле «Ключ доступа сервера»
в настройках Android и веб-приложения. Ключ не выводится установочным скриптом.
Для ручного запуска задайте `MUSIC_API_TOKEN_FILE` или `MUSIC_API_TOKEN`.

По умолчанию CORS разрешает только текущий origin. Если веб-клиент размещён отдельно,
добавьте точные разрешённые origins через `/etc/music-api/environment`:

```ini
MUSIC_ALLOWED_ORIGINS=http://localhost:5173,https://music.example.com
```

Для доступа за пределами доверенной сети используйте HTTPS: ключ и аудио по обычному
HTTP не шифруются. Публичное чтение без ключа — сознательная настройка этого сервера;
защита записи не превращает его в публичный хостинг с учётными записями.

Проверка после установки: `systemctl status music-api` и `ps -o user= -p "$(systemctl show -p MainPID --value music-api)"`.
Положите аудиофайлы в `/srv/music` (можно с подпапками).

## Адреса для приложения

- LAN: `http://192.168.1.80:8080`
- Tailscale: `http://<tailscale-ip>:8080`

Узнать Tailscale IP: `tailscale ip -4`.

На этом устройстве:

- LAN: `http://192.168.1.80:8080`
- Tailscale: `http://100.106.26.26:8080`
